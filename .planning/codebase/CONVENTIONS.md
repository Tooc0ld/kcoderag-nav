# Coding Conventions

**Analysis Date:** 2026-08-28

## Naming Patterns

### Files

- Canonical modules use kebab-case `.cts` names such as `grep-nudge.cts`, `host-adapter.cts`, and
  `pack-audit.cts`.
- Tests use `*.test.cts`; compiled paths preserve the same structure under `dist-tests/`.
- Generated assets keep host-native names and paths. Compatibility manifests and MCP keys must not
  be renamed independently of the generator.

### Symbols

- Functions and locals use descriptive `camelCase`.
- Interfaces and exported type names use `PascalCase`.
- Module constants use `SCREAMING_SNAKE_CASE`.
- Stable host, command, capability, and inventory collections are readonly and frozen.

## Code Style

- TypeScript is strict with `noUncheckedIndexedAccess` and `exactOptionalPropertyTypes`.
- Runtime imports use Node built-ins only. Do not add a production dependency, runtime transpiler,
  or package without the dependency audit gate.
- Executable sources use a Node shebang and concise module docstring where appropriate.
- Preserve two-space indentation, semicolons, readable line lengths, and LF-normalized deterministic
  generated bytes.
- Published and installed execution is compiled CommonJS; never require runtime TypeScript
  compilation or Python.

## Import Organization

1. Import Node built-ins with `node:` specifiers.
2. Import sibling TypeScript modules using emitted `.cjs` suffixes so compiled resolution is direct.
3. Keep host-specific imports outside `src/core/`; CLI code reaches adapters through
   `src/hosts/index.cts` and the `HostAdapter` contract.

## Error Handling

- Expected refusals use stable `InstallError` codes and optional safe relative paths.
- Never include file contents, URLs, headers, bearer values, or subprocess/configuration bodies in
  public errors.
- Mutating commands validate runtime, source conflicts, support, ownership, drift, and complete
  desired state before one `applyTransaction` call.
- Hook boundaries catch malformed, oversized, unsupported, and operational errors; they emit no
  protocol noise, exit successfully, and never reject the original host operation.
- `status` and `doctor` are read-only. `--json` emits exactly one stable JSON value.

## Logging

- Hook stdout contains only a valid host protocol response and is otherwise empty.
- Launchers suppress runtime stderr and fail open.
- CLI and maintainer diagnostics contain stable codes and safe paths only.
- Receipts and smoke artifacts contain metadata-only fields. `NOT_RUN` is never converted to `PASS`.

## Comments and Documentation

- Use module/function docstrings for ownership, transaction, protocol, and fail-open boundaries.
- Comments explain non-obvious safety policy, deterministic ordering, host differences, and why
  connection values remain opaque; do not restate syntax.
- Installation, host compatibility, routing, hook, update, and release guidance belongs in the
  repository-local `docs/MCP_QA_EXPERIENCE_GUIDE.md`.

## Function Design

- Prefer pure read/render functions returning immutable data.
- Keep filesystem mutation inside `src/core/transaction.cts`.
- Inject clocks, fetchers, spawners, and failure points where deterministic tests must prove timing,
  network separation, or rollback behavior.
- Narrow unknown values at trust boundaries before use; do not spread unchecked host payloads into
  core logic.

## Module Design

- `src/core/` is host-neutral.
- `src/hosts/` owns native paths, structured merge rules, source detection, and desired-state render.
- `src/cli/` owns orchestration and output policy, not writes.
- `src/generator/` renders sorted bytes from canonical templates and never exposes credential inputs.
- `src/hooks/` owns bounded advisory runtime behavior.
- Generated QA/Cursor trees are products, not independent maintenance sources.

## Git and Scrub Discipline

- Preserve unrelated dirty and untracked work.
- Stage task paths explicitly; never use blanket staging or destructive working-tree cleanup.
- Documentation neutralization uses an explicit-path private scrub baseline before edits, an ordinary
  atomic commit, immutable scoped audit, and post-commit preservation assertion.
