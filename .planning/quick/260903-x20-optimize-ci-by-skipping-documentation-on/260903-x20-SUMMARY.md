# Quick 260903-x20: CI packaged-smoke optimization

The expensive five-host packaged lifecycle now runs once per event instead of once per OS/Node lane. Ordinary source and launcher coverage remains on Windows/Linux with Node 22/24.

## Changes

- Acceptance push events now ignore only `README.md`, `docs/**`, and `.planning/**`. Product sources, generated assets, workflow files, and package metadata still trigger acceptance.
- Exact-candidate acceptance still builds one immutable artifact and retains the protected self-hosted LIVE lane, but has one hosted `PACKAGED / windows-node22` consumer instead of four consumers.
- Pull-request and manual CI retain the four-platform ordinary matrix and use one `Packaged readiness / windows-node-22` job. Branch pushes continue to delegate packaged coverage to acceptance.
- Release CI retains its four-platform ordinary matrix, but runs `smoke:required` and the pre-publish tarball audit once in an independent Windows Node 22 job. Publish now needs both required jobs.
- The acceptance validator fails closed unless the exact documentation filter and singleton packaged topology remain present.
