## 迁移边界与安装入口

### JavaScript 迁移覆盖哪些代码？

| Option | Description | Selected |
|--------|-------------|----------|
| 完整迁移 | Hook、更新检查、安装器、生成器、pre-commit 和测试全部迁移，发布包无 Python 运行代码 | ✓ |
| 只迁移运行路径 | 用户运行路径改为 JS，仓库维护脚本和测试继续使用 Python | |
| 仅增加 npx 外壳 | npx 继续调用仓库中的 Python 实现 | |

**User's choice:** 完整迁移。
**Notes:** TypeScript 维护源码，构建为直接运行的 CJS；不使用 `ts-node` 或运行时编译。

### npx 与宿主原生 marketplace 如何分工？

| Option | Description | Selected |
|--------|-------------|----------|
| npx 统一主入口并保留 marketplace | npx 为默认，marketplace 仍作为可选分发 | |
| npx 只补缺口 | 只替代 Codex 项目级和 Cursor，本地 Claude 仍走 marketplace | |
| npx 完全替代 marketplace | 三宿主都由 npx 写入项目原生配置 | ✓ |

**User's choice:** npx 完全替代 marketplace。
**Notes:** 当前交付不再依赖宿主 marketplace。

### 执行 install 时怎样选择宿主？

| Option | Description | Selected |
|--------|-------------|----------|
| 交互选择，自动化显式 `--host` | 无参数选择 Codex/Claude/Cursor；脚本显式指定 | ✓ |
| 自动检测并安装所有宿主 | 扫描项目后同时修改多个宿主 | |
| 默认 Codex | 无参数直接安装 Codex，其他宿主显式指定 | |

**User's choice:** 交互选择，自动化显式 `--host`。
**Notes:** 一次调用只修改所选宿主。

### 现有 Python 版安装如何迁移？

| Option | Description | Selected |
|--------|-------------|----------|
| 原地安全迁移 | 校验旧状态和漂移后原子替换，保留环境 | ✓ |
| 先卸载再安装 | 用户手工清理 Python 版后重新安装 | |
| 无条件覆盖 | 不检查受管内容是否被修改 | |

**User's choice:** 原地安全迁移。
**Notes:** 漂移时写前硬停止，只删除确认属于旧安装器的 Python 文件。

## npm 发布与版本语义

### npm 安装包采用哪个名称？

| Option | Description | Selected |
|--------|-------------|----------|
| `kcoderag-nav` | 未 scoped 公共包，命令最短 | ✓ |
| `@tooc0ld/kcoderag-nav` | scoped 公共包 | |
| 仅从 GitHub 源运行 | 不发布 npm registry 包 | |

**User's choice:** `kcoderag-nav`。
**Notes:** 标准命令为 `npx kcoderag-nav@latest install`；查询时包名看似未占用，最终以首次发布为准。

### 哪个文件作为唯一版本源？

| Option | Description | Selected |
|--------|-------------|----------|
| 根 `package.json` | npm 与所有生成产物共用一个版本 | ✓ |
| 保留 `plugin-src/version.txt` | npm 构建时读取现有版本文件 | |
| npm 与宿主版本分离 | 分别维护多个版本号 | |

**User's choice:** 根 `package.json`。
**Notes:** QA/Dev/Cursor manifest 与 install state 全部派生该版本。

### 什么时候发布到 npm？

| Option | Description | Selected |
|--------|-------------|----------|
| 版本标签触发 | release script 建标签，CI 测试构建后发布 | ✓ |
| 每次 master push | 每个主分支提交都发布新版 | |
| 本地手工 publish | 维护者在本机直接发布 | |

**User's choice:** 版本标签触发。
**Notes:** `npm run release:patch|minor|major` 创建 `vX.Y.Z`；普通 master push 只测试。

### 异步更新检查以哪里为版本源？

| Option | Description | Selected |
|--------|-------------|----------|
| npm Registry `latest` | 与用户实际安装来源一致 | ✓ |
| GitHub `package.json` | 继续直接检查代码仓库 | |
| 取消自动检查 | 完全依赖用户主动更新 | |

**User's choice:** npm Registry `latest`。
**Notes:** 24 小时缓存、后台刷新、fail-open，提示运行 `npx kcoderag-nav@latest update`。

## 宿主项目边界与落盘位置

### 三种宿主采用哪种落盘策略？

| Option | Description | Selected |
|--------|-------------|----------|
| 项目原生配置 | 写入各宿主公开的项目级目录和配置 | ✓ |
| 未公开插件缓存 | 模拟 marketplace 内部缓存布局 | |
| 重新保留 marketplace | 继续维护宿主 marketplace 安装 | |

**User's choice:** 项目原生配置。
**Notes:** Codex 使用 `.codex`/`.agents`，Claude 使用 `.claude`/根 `.mcp.json`，Cursor 使用 `.cursor`；对外称项目集成。

### install 默认目标是哪一个目录？

| Option | Description | Selected |
|--------|-------------|----------|
| 当前目录并确认 | 显示规范化绝对路径，允许 `--target` 覆盖 | ✓ |
| 自动寻找 Git/SVN 根 | 从当前目录逐级向上寻找仓库标记 | |
| 始终要求 `--target` | 不提供交互默认值 | |

**User's choice:** 当前目录并确认。
**Notes:** 不依赖 Git/SVN 根发现，支持 `I:\JX3_SVN\Head` 这类目标。

### 已有宿主配置文件如何处理？

| Option | Description | Selected |
|--------|-------------|----------|
| 结构化合并和 section 所有权 | 只管理 KCodeRag 内容，保留其他配置 | ✓ |
| 仅接受空配置 | 已有配置就拒绝安装 | |
| 覆盖整个配置文件 | 以生成内容替换用户配置 | |

**User's choice:** 结构化合并和 section 所有权。
**Notes:** 受管内容漂移时 update/uninstall 在写前硬停止。

### 同一项目是否允许多个宿主适配器？

| Option | Description | Selected |
|--------|-------------|----------|
| 跨宿主共存，每次安装一个 | 可重复执行，为不同宿主分别安装 | ✓ |
| 一次多选并全事务安装 | 一个命令同时安装多个宿主 | |
| 项目只能安装一个宿主 | Codex/Claude/Cursor 相互排斥 | |

**User's choice:** 跨宿主共存，每次安装一个。
**Notes:** QA/Dev 只在同一宿主内部互斥；OpenCode 留作后续 adapter。

## Node 兼容与失败恢复

### npm 包最低支持哪个 Node.js 版本？

| Option | Description | Selected |
|--------|-------------|----------|
| Node.js 22+ | 覆盖当前 Node 22/24 LTS | ✓ |
| Node.js 24+ | 只支持最新 LTS | |
| Node.js 20+ | 兼容已经 EOL 的旧版本 | |

**User's choice:** Node.js 22+。
**Notes:** CI 同时覆盖 Node.js 22 和 24。

### 安装后 Node.js 缺失或版本损坏时如何处理？

| Option | Description | Selected |
|--------|-------------|----------|
| 写操作硬停止，hook fail-open | install/update 拒绝写入；hook 静默；status/doctor 报告 | ✓ |
| 所有入口硬停止 | hook 也阻止原始工具调用 | |
| 所有入口静默忽略 | 安装器和诊断不报告问题 | |

**User's choice:** 写操作硬停止，hook fail-open，status/doctor 报告。
**Notes:** 保持搜索工具永不被 hook 运行时故障阻断。

### npm 或网络不可用时如何处理？

| Option | Description | Selected |
|--------|-------------|----------|
| 冷安装无网不写入，已安装离线可用 | npx 获取失败明确报错；hook 与缓存继续工作 | ✓ |
| 复制完整 npm 包进项目 | 为离线重装长期保留安装包 | |
| 所有操作都要求联网 | hook 执行也依赖网络 | |

**User's choice:** 冷安装无网不写入，已安装功能离线可用。
**Notes:** 更新检查失败静默 fail-open，不阻塞首次相关工具调用。

### 单宿主安装或更新失败时如何恢复？

| Option | Description | Selected |
|--------|-------------|----------|
| 整宿主原子回滚 | 预检、写入计划、备份，失败后完整恢复该宿主 | ✓ |
| 逐文件尽力写入 | 保留成功文件并报告残留 | |
| 用户手工修复 | 不提供自动回滚 | |

**User's choice:** 整宿主原子回滚。
**Notes:** 不回滚或触碰同一项目中的其他宿主；漂移时写前硬停止。
