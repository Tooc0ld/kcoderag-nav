## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Preserved allowed local GSD state across the audited release**
- **Found during:** Task 3 readiness/dry-run
- **Issue:** The helper allowed local `.planning`/`.gsd` state at preflight but later compared the full repository status against an exact release-only diff, contradicting that contract.
- **Fix:** Excluded only the audited local-state paths from release diff equality while retaining complete before/after preservation checks.
- **Files modified:** `src/maintainer/release.cts`, `tests/maintainer/release.test.cts`
- **Committed in:** `0fbf3d7`

**2. [Rule 1 - Bug] Made release gates independent of developer-machine state**
- **Found during:** Failed `v0.1.5` GitHub Release run
- **Issue:** Tests assumed a local sibling guide repository and a fixed next version, while the tracer inherited local npm authorization configuration; those assumptions broke or contaminated clean-runner execution.
- **Fix:** Injected a temporary guide fixture, derived the patch version dynamically, and removed inherited npm auth seams from the tracer subprocess.
- **Files modified:** `tests/maintainer/docs-check.test.cts`, `tests/maintainer/release.test.cts`, `tests/tracer/codex-install.test.cts`
- **Committed in:** `11c88fd`

**3. [Rule 1 - Bug] Removed Windows path-representation ambiguity from repository-root validation**
- **Found during:** Required Windows CI after the clean-runner fixes
- **Issue:** Git and Node represented the same Windows checkout through different canonical path forms, causing a false `repository_root_required` refusal.
- **Fix:** Replaced filesystem-string root equality with Git's empty `rev-parse --show-prefix` root invariant, retaining subdirectory refusal and alias acceptance.
- **Files modified:** `src/maintainer/release.cts`, `tests/maintainer/release.test.cts`
- **Committed in:** `8770ef5`, `2741cff`

### User-Approved Architectural Deviation

**4. [Rule 4 - Decision] Published `0.1.6` after the immutable `v0.1.5` attempt failed**
- **Found during:** Task 3 release workflow
- **Issue:** npm versions and Git tags are immutable release evidence; reusing or moving `v0.1.5` would violate the release contract.
- **Decision:** The user explicitly authorized `0.1.6` as the first successful public version and required failed `v0.1.5` to remain unchanged.
- **Impact:** npm has no published `0.1.5`; `0.1.6` is the first public package and current `latest`.
- **Committed in:** `5ff0a97`
