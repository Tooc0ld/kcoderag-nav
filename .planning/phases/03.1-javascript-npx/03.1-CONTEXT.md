# Phase 03.1: JavaScript 与 npx 安装运行时迁移 - Context

**Gathered:** 2026-08-23
**Status:** Ready for planning

<domain>
## Phase Boundary

将 KCodeRag Nav 的 Hook、异步更新检查、Codex/Claude Code/Cursor 项目安装器、生成器、
pre-commit 与自动化测试从 Python 完整迁移到 TypeScript 维护源码和可直接运行的 JavaScript/CJS，
并发布统一的 `npx kcoderag-nav@latest ...` CLI。迁移必须保留现有 QA/Dev 互斥、项目边界、
受管内容漂移保护、hook advisory/fail-open、三宿主原生项目配置和权威指南同步约束。

本阶段不交付 OpenCode 适配器，也不处理生产级凭据、HTTPS 或身份系统。

</domain>

<decisions>
## Implementation Decisions

### 迁移边界与安装入口

- **D-01:** 完整迁移 Hook、更新检查、项目/Cursor 安装器、生成器、pre-commit 和测试；发布包不再包含 Python 运行代码。— **Reversibility:** costly — 恢复 Python 会同时改动安装契约、生成产物、CI 和全部测试入口。
- **D-02:** 使用 TypeScript 作为维护源码，构建出可直接由 Node.js 执行的 CJS；禁止 `ts-node` 或用户机器上的运行时编译。
- **D-03:** `npx` 完全替代 Codex、Claude Code 与 Cursor 的 marketplace 用户安装流程；当前交付不再依赖任一宿主的 marketplace。— **Reversibility:** costly — 恢复 marketplace 需要重新维护三套宿主分发元数据、安装说明和升级路径。
- **D-04:** 未传 `--host` 时交互选择 Codex、Claude Code 或 Cursor；自动化使用 `--host codex|claude|cursor`，一次命令只修改所选宿主。
- **D-05:** 旧 Python 安装原地安全迁移：读取旧 `install-state.json`，校验受管内容无漂移后原子替换为 JS/CJS，保留当前 QA/Dev；漂移时写前硬停止，只删除能够确认由旧安装器管理的 Python 文件。

### npm 发布与版本语义

- **D-06:** 发布未 scoped 公共包 `kcoderag-nav`，标准入口为 `npx kcoderag-nav@latest install`。— **Reversibility:** one-way — 包名和命令一旦发布并被项目文档引用，就成为外部安装契约，改名需要兼容包和用户迁移。
- **D-07:** 根目录 `package.json` 是唯一版本源；npm 包、QA/Dev/Cursor manifest 和安装状态都从该版本生成。— **Reversibility:** costly — 更换版本源会影响发布、生成器、更新检测和已安装状态比较。
- **D-08:** 使用 `npm run release:patch|minor|major` 生成 `vX.Y.Z` 标签；GitHub Actions 在标签上测试、构建并发布，普通 `master` push 只测试、不发布。
- **D-09:** 异步更新检查查询 npm Registry 的 `kcoderag-nav` `latest`；每会话首次相关工具调用只启动后台刷新，缓存 24 小时并 fail-open，升级提示使用 `npx kcoderag-nav@latest update`。

### 宿主项目边界与落盘位置

- **D-10:** 不使用 marketplace 后，直接管理宿主官方项目配置：Codex 使用 `.codex/` 与 `.agents/skills/`；Claude Code 使用 `.claude/settings.json`、`.claude/skills/` 和项目根 `.mcp.json`；Cursor 使用 `.cursor/rules/`、`.cursor/skills/` 和 `.cursor/mcp.json`。这套能力对外称为 KCodeRag Nav 项目集成，不声称是 marketplace plugin。— **Reversibility:** costly — 路径成为已安装项目中的持久配置和卸载所有权边界。
- **D-11:** `install` 默认目标是当前目录；写入前展示规范化绝对路径并确认。`--target PATH` 可覆盖，不自动寻找 Git/SVN 根。
- **D-12:** 对已有 JSON/配置进行结构化合并，只拥有 KCodeRag section 和独占受管文件；保留无关配置。受管 section 或文件漂移时，`update`/`uninstall` 在写入前硬停止。
- **D-13:** 同一项目允许 Codex、Claude Code、Cursor 跨宿主共存；每次调用只安装一个宿主，可重复执行增加其他宿主。QA/Dev 只在同一宿主内部互斥，跨宿主 QA 共存是正常状态。
- **D-14:** 安装器核心使用可扩展 host adapter 接口，便于未来增加 OpenCode，而不要求重写事务、状态和所有权逻辑。

### Node 兼容与失败恢复

- **D-15:** 最低支持 Node.js 22；CI 同时覆盖 Node.js 22 与 24 LTS，不支持已经 EOL 的 Node.js 20。
- **D-16:** `install`/`update` 在任何项目写入前检查 Node.js 22+，不满足时硬停止；已经部署的 hook 若 Node 缺失、版本损坏或启动异常，必须静默 fail-open；`status`/`doctor` 明确报告运行时问题。
- **D-17:** 首次 `npx` 获取包因 npm/网络失败时给出明确错误且不写目标项目；已安装 hook 完全离线运行；后台更新检查使用缓存并静默 fail-open，网络失败不得进入工具调用的阻塞路径。
- **D-18:** 每次安装或更新是单宿主原子事务：先完成所有校验并生成写入计划，再备份本次涉及的文件；任何一步失败都恢复该宿主安装前状态，不回滚或改动同项目其他宿主。

### Agent 自主决策

- TypeScript 源码的内部目录拆分、类型组织、编译器和测试运行器由规划与实现决定，但必须满足 Node.js 22+、发布 CJS、无运行时编译和发布包无 Python 运行代码。
- 原子写入所用的临时文件命名、备份格式和内部事务 API 可按现有跨平台约束设计；不得削弱写前漂移检查或单宿主回滚边界。
- CLI 的提示文案、颜色和进度呈现可采用常规跨平台 CLI 体验，但自动化的 `--json` 输出必须稳定且不混入诊断噪音。

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets

- `plugin-src/` 已是 QA/Dev/Cursor 的单一规范源，可保留模板和环境数据，只替换 Python 执行逻辑与版本源。
- `plugin-src/hooks/grep_nudge.py` 的纯函数分类、输入长度边界和顶层异常捕获可直接映射为 TypeScript 模块与 CJS 入口。
- 现有安装器已经实现受管状态、hash 漂移检测、QA/Dev 互斥、幂等 install/status/update/uninstall，可作为 JS 行为基线。
- 现有 `tests/stub_mcp_server.py`、host smoke 与表驱动 hook cases 提供迁移前的契约样本；JS 测试应保持这些场景而不是重新定义行为。

### Established Patterns

- 规范源生成 `kcoderag-qa/`、`kcoderag-dev/` 与 `kcoderag-cursor/` 自包含产物；生成结果必须确定且支持只读 drift check。
- Hook 只输出协议 JSON，异常和无关搜索静默退出成功；诊断信息不能污染 stdout。
- 安装器只修改目标项目中明确拥有的文件/section，敏感 MCP 配置可被复制但不得输出 Bearer 值。
- CI 当前同时覆盖 Windows/Linux、生成检查、单元测试、两份生成 hook 回归与可选真实宿主 smoke；迁移后应改为 Node 22/24 矩阵并保持宿主验证边界。

### Integration Points

- 新根 `package.json` 承担 npm metadata、`bin`、唯一版本源、build/test/release scripts 和 Node engine 限制。
- Host adapter 连接共享 CLI/事务层与 Codex、Claude Code、Cursor 各自的路径、配置合并和 hook/Rule 资产。
- 编译后的 CJS launcher 替换 `plugin-src/hooks/*.py` 与 Python 探测逻辑，并由生成器复制进各环境产物。
- JS pre-commit 与 GitHub Actions 取代 Python 生成检查；发布 job 仅在 `vX.Y.Z` 标签触发。
- 文档变更同时落在本仓库 `README.md` 和 `../KCodeRag/MCP_QA_EXPERIENCE_GUIDE.md`，后者保持唯一权威体验指南。

</code_context>

<specifics>
## Specific Ideas

- 用户希望安装体验接近 GSD 这类多宿主工具：一个 `npx` CLI 负责选择宿主并写入宿主原生项目目录，而不是要求用户先 `git clone` 再手工调用 Python。
- 包名采用 `kcoderag-nav`；讨论时公开 npm 查询未发现同名包，但最终可用性只能由首次发布确认。
- 普通用户仍默认 QA；Dev 只用于开发/测试并需要显式选择。安装一个宿主不应自动修改另外两个宿主。
- `status`/`doctor` 必须让用户直接看见安装环境、运行时问题、受管文件漂移和来源状态，无需手翻 `install-state.json`。

</specifics>
