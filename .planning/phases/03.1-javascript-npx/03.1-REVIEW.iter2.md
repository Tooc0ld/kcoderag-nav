# Phase 03.1: Code Review Report

## Narrative Findings (AI reviewer)

The canonical TypeScript, host adapters, transaction boundary, generated products, hook runtime,
maintainer gates, smoke harness, and tests were reviewed. Generated QA/Dev hook CJS hashes match the
compiled canonical hook modules, and `generate:check` confirms the generated trees are current.

`npm run build`, all 142 tests, `npm run generate:check`, and `npm run pack:audit` pass. Those results
do not cover the section-ownership, credential-snapshot, staged-tree, post-commit failure, or
filesystem-race cases below.

## Summary

The implementation has five blockers. Most seriously, it persists complete pre-existing MCP/config
files as base64 inside project install-state files, duplicating unrelated credentials despite the
explicit no-snapshot boundary. The same whole-file state model mistakes unrelated user edits for
managed drift. Codex can also silently rewrite invalid UTF-8 bytes or append a duplicate TOML table,
and the path validation is vulnerable to a check/use symlink swap.

Five release and maintainability warnings remain: pre-commit checks the working generated tree
instead of the staged generated blobs, release failures can leave a commit/tag behind, pack audit
derives its allow-list from arbitrary ignored `dist/` contents, an obsolete tracer installer remains
published, and session-less update checks can run once per hour rather than once per session.

## Critical Issues

### CR-01: Install state snapshots unrelated credential-bearing configuration

**Classification:** BLOCKER
**Files:**
`D:/AIProgram/kcoderag-nav/src/hosts/codex.cts:260-263,384-396,535-545`;
`D:/AIProgram/kcoderag-nav/src/hosts/claude.cts:197-198,278-286,330-341`;
`D:/AIProgram/kcoderag-nav/src/hosts/cursor.cts:191-192,453-461,500-511`

**Issue:** Each adapter reads the complete shared config (`.codex/config.toml`, `.codex/hooks.json`,
root `.mcp.json`, `.claude/settings.json`, or `.cursor/mcp.json`), base64-encodes it, and writes it
into the persistent project install state. Those files may contain credentials for unrelated MCP
servers. Base64 is reversible, so installation creates a second credential snapshot in a different
project file that can be indexed, backed up, or committed. This directly violates the project's
rule that MCP values must never be snapshotted.

**Fix:** Replace whole-file `OriginalRecord` values for shared configuration with section-level
ownership metadata: managed key/entry identity, managed-section digest, and only non-sensitive
splice/format metadata needed for removal. On uninstall, parse the current document and remove only
the owned KCodeRag entry/hook/block. Add fixtures whose unrelated MCP entries contain sentinel
credentials and assert that no install-state/recovery-success artifact contains the sentinel.

### CR-02: Whole-file digests break declared section ownership

**Classification:** BLOCKER
**Files:**
`D:/AIProgram/kcoderag-nav/src/hosts/codex.cts:356-361,535-555,602-609`;
`D:/AIProgram/kcoderag-nav/src/hosts/claude.cts:249-255,330-351,367-370`;
`D:/AIProgram/kcoderag-nav/src/hosts/cursor.cts:409-415,500-521,540-543`

**Issue:** State records the digest of the entire rendered shared configuration file, detection
compares the entire current file to that digest, and uninstall restores the entire original file.
Consequently, a user adding an unrelated MCP server, permission, hook, or TOML setting after install
is reported as `managed_content_changed`; update and uninstall hard-stop even though the KCodeRag
section is intact. This contradicts the documented ownership boundary and can strand an otherwise
healthy installation.

**Fix:** Digest only the owned KCodeRag section/hook entry. For update/uninstall, parse the current
file, verify that owned section, merge the new/removal result into the current unrelated content,
then pass the whole current-file digest to the transaction solely as the race guard. Add lifecycle
tests that edit unrelated content after install and prove update/uninstall succeeds while preserving
that edit.

### CR-03: Non-fatal UTF-8 decoding can silently corrupt existing config bytes

**Classification:** BLOCKER
**Files:**
`D:/AIProgram/kcoderag-nav/src/hosts/codex.cts:124,193-197`;
`D:/AIProgram/kcoderag-nav/src/hosts/claude.cts:96`;
`D:/AIProgram/kcoderag-nav/src/hosts/cursor.cts:93`

**Issue:** `Buffer.toString("utf8")` does not throw on invalid UTF-8; it replaces malformed byte
sequences with U+FFFD. The `try/catch` in `renderConfig` therefore never produces `invalid_utf8`, and
JSON strings containing malformed bytes can likewise parse after replacement. The adapters then
serialize the replacement character, permanently changing unrelated user bytes during install.

**Fix:** Decode every user-controlled structured config with
`new TextDecoder("utf-8", { fatal: true }).decode(bytes)` and translate decode failures to the safe
path-only error. Add invalid-byte fixtures for TOML and every JSON config and assert zero writes and
byte-for-byte preservation.

### CR-04: Codex conflict detection misses legal TOML spellings of the managed table

**Classification:** BLOCKER
**File:** `D:/AIProgram/kcoderag-nav/src/hosts/codex.cts:199-203,210-223`

**Issue:** The conflict regex recognizes only a narrow `[mcp_servers.kcoderag-*]` table header.
Legal TOML forms such as `[mcp_servers . "kcoderag-qa"]`, quoted parent keys, dotted assignments, or
an inline `mcp_servers` table are missed. The installer then appends another definition of the same
key/table, producing invalid or ambiguous Codex configuration instead of refusing before writes.

**Fix:** Use a TOML-aware parser/validator or a complete bounded parser for the managed key path,
and reject every pre-existing semantic definition of `mcp_servers.kcoderag-qa` or `-dev` before
rendering. Add fixtures for whitespace-separated dotted keys, quoted keys, dotted assignments, and
inline tables, with zero-write assertions.

### CR-05: Path checks are not bound to the filesystem objects later read and replaced

**Classification:** BLOCKER
**Files:**
`D:/AIProgram/kcoderag-nav/src/core/project-target.cts:68-103`;
`D:/AIProgram/kcoderag-nav/src/core/transaction.cts:45-50,73-98,235-265,273-320`

**Issue:** Ancestors and destinations are checked with `lstatSync`, then reopened later by pathname
for reads, temporary creation, rename, unlink, and rollback. A concurrent process can replace a
checked directory or file with a symlink/junction between check and use. The CLI can then read from
or write outside the explicit project root; a raced read is especially dangerous because CR-01
persists the captured bytes in state. Rollback uses the same unbound paths.

**Fix:** Bind mutations to verified directory identities and no-follow operations (descriptor-
relative `openat`/rename equivalents where available), or fail closed on platforms where that
cannot be guaranteed. At minimum, track parent identity, re-resolve and compare every ancestor
immediately before each read/rename/unlink and again during rollback. Add a deterministic injected
swap seam that replaces an ancestor after validation and prove no outside read/write occurs.

## Warnings

### WR-01: Pre-commit can approve stale staged generated blobs

**Classification:** WARNING
**File:** `D:/AIProgram/kcoderag-nav/src/maintainer/pre-commit.cts:143-158,198-217`

**Issue:** Unstaged-change detection covers only canonical paths. `generate:check` inspects the
working tree, while `indexMatches` merely proves the index did not change. If stale generated blob A
is staged and correct generated blob B is left only in the working tree, the check sees B, keeps A
unchanged, and returns `verified`. Existing partial-staging tests exercise `package.json`, not a
generated path.

**Fix:** Reject unstaged differences under `GENERATED_PATHS` too, or compare every canonical
generated working blob directly with its staged blob after `generate:check`. Add the A-in-index,
B-in-worktree regression fixture and require `generation_drift`/`generated_unstaged_changes`.

### WR-02: A failed release can leave a successful release commit or tag behind

**Classification:** WARNING
**File:** `D:/AIProgram/kcoderag-nav/src/maintainer/release.cts:326-367`

**Issue:** `committed` becomes true immediately after `git commit`. Any later failure—commit
write-set verification, ignored-state verification, tag creation/signing, tag verification, or the
final clean check—skips `restoreReleaseFiles`. The helper returns failure while leaving the branch
advanced and possibly the tag created, so a retry begins from mutated release state.

**Fix:** Record the original HEAD and exact created commit/tag, then compensate post-commit failures
only when HEAD/tag still match those exact objects; alternatively construct and validate the commit
without moving refs and update branch/tag refs transactionally. Add injected failures immediately
after commit and immediately after tag and assert the documented recovery state exactly.

### WR-03: Pack audit treats arbitrary ignored `dist/` files as expected

**Classification:** WARNING
**Files:** `D:/AIProgram/kcoderag-nav/package.json:9-10`;
`D:/AIProgram/kcoderag-nav/src/maintainer/pack-audit.cts:119-146,206-231`

**Issue:** The package policy includes the entire ignored `dist/` directory. `expandPackageFiles`
walks whatever happens to be present and uses that live set as `expectedPaths`, so an unexpected or
stale compiled file is accepted as part of the exact archive. The credential-sentinel and unresolved
placeholder scans also explicitly skip every `dist/` entry.

**Fix:** Derive an immutable compiled-output manifest from the canonical source list (or list exact
published CJS paths), reject extra `dist/` files, and scan compiled runtime entries with a policy
appropriate for code. Add an unexpected ignored `dist/extra.cjs` fixture and require audit failure.

### WR-04: The obsolete tracer installer remains compiled and published

**Classification:** WARNING
**Files:** `D:/AIProgram/kcoderag-nav/src/tracer/codex-install.cts:1,451-527`;
`D:/AIProgram/kcoderag-nav/package.json:9-10,48`

**Issue:** The module says it is retained only until the full Codex adapter lands, but that adapter
now exists. The tracer still exposes a second mutable `installCodexQa` implementation, is tested as
an active path, compiles under `dist/tracer/`, and is included in the npm tarball. It already diverges
from the canonical multi-environment adapter and duplicates the same whole-file/UTF-8 defects.

**Fix:** Remove the tracer source and tests now that `src/hosts/codex.cts` is canonical, clean stale
compiled output, and make the exact pack manifest reject `dist/tracer/codex-install.cjs`.

### WR-05: Session-less update scheduling is hourly, not once per session

**Classification:** WARNING
**File:** `D:/AIProgram/kcoderag-nav/src/hooks/update-check.cts:166-184,199-210`

**Issue:** When the host payload has no session/thread/conversation ID, the marker key uses cwd plus
the current hour. A long session with repeated refresh failures can therefore spawn a new detached
registry worker every hour, contrary to the documented first-eligible-event-per-session contract.

**Fix:** Have the launcher create one private random session token for its host session when the
protocol lacks an ID, or use a bounded process/session marker with an explicit lifetime that does
not rotate hourly. Add a test using the same session-less payload on opposite sides of an hour and
assert only one claim.
