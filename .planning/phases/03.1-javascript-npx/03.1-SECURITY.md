# Phase 03.1 — Security

> Per-phase security contract for the JavaScript/CJS runtime, npx lifecycle, host adapters, hooks, maintainer tooling, smoke evidence, and release path.

---

## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| CLI input → project target | Host, environment, target, and lifecycle intent are normalized before any selected-host mutation. | Paths, host identity, environment choice |
| Project configuration → host adapter | Untrusted JSON/TOML and existing project files are parsed without granting ownership of unrelated bytes or sections. | Project configuration; may contain credentials |
| Adapter desired state → transaction | Read/render-only adapters hand one complete selected-host plan to the sole filesystem commit boundary. | Managed paths, expected digests, section provenance |
| Legacy user state → Cursor migration | User-level legacy state is read by default and removed only with separate authority, exact ownership evidence, and recoverable migration. | Legacy plugin files and state metadata |
| Host hook input → advisory output | Untrusted bounded hook payloads can only produce fail-open advisory protocol output; update work is detached. | Tool event metadata; no credential logging |
| Templates and source → generated package | Canonical templates and compiled CJS cross deterministic generation and exact archive allow-list gates. | Runtime code, launchers, skills, Rules, manifests |
| Public npm specifier → verified artifact | Exact/latest acquisition crosses an untrusted network and npm configuration boundary before any package bytes may be executed. | Registry metadata, tarball URL, SRI, SHA-256/SHA-512, installed manifest |
| Verified public artifact → synthetic lifecycle | The original Registry tarball is repacked with a loopback MCP endpoint; source identity and per-invocation lifecycle bytes remain distinct, explicitly bound evidence. | Frozen public identity, synthetic tgz digest, three-host lifecycle outcomes |
| Git/tag/workflow → npm publication | A version tag and exact commit enter a required Windows/Linux × Node 22/24 matrix before the secret-bearing publish job. | Source provenance, package tarball, publish credential presence |
| Cross-repo guide → provenance receipt | The authoritative sibling guide is updated and verified without exposing content or disturbing unrelated work. | Path/status/hash metadata only |
| Cleanup authorization → filesystem deletion | Immutable receipts and exact inventories authorize only verified unlink and non-recursive rmdir operations. | Relative paths, hashes, deletion evidence |
