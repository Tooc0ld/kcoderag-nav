# Phase 03.1 Plan 08: Asynchronous npm Update Awareness Summary

**Installed hooks now read only a validated local cache in the foreground while a strict, detached npm Registry worker refreshes latest-version state without entering the tool-call critical path.**

## Accomplishments

- Added a zero-network foreground cache/session state machine with an exact 24-hour TTL, strict installed/latest version comparison, hashed bounded markers, and one notice or refresh attempt per session.
- Added a detached npm Registry worker with a fixed HTTPS package endpoint, 1.5-second request budget, response-size/content/schema/semver checks, global refresh lock, and atomic cache replacement.
- Integrated cached notices into the advisory hook after its output decision while keeping structural guidance operational if update modules, cache state, permissions, Node networking, or the registry are unavailable.

- `tests/hooks/update-check.test.cts` - Fake clock/files/spawn coverage plus offline injected Registry worker and hook-order integration tests.

## Decisions Made

- Used one package-level `latest` cache and installed `packageVersion`, matching npm as the sole version authority rather than retaining environment-specific GitHub update indexes.
- Kept the foreground module free of `node:https`; it may synchronously inspect small local files and spawn one detached process, but it never waits for registry work.
- Required the worker response to identify `kcoderag-nav` and expose a strict stable `dist-tags.latest`; redirects, non-HTTPS identity, unexpected content types, oversized bodies, malformed JSON, prereleases, and write failures are ignored.

- **Found during:** Task 2 integration review
- **Issue:** The first implementation deduplicated stale refresh spawns but could repeat a known update notice on every relevant tool call in one session.
- **Fix:** Reused the hashed exclusive session marker for both fresh-cache notice delivery and stale-cache scheduling.
- **Files modified:** `src/hooks/update-check.cts`, `tests/hooks/update-check.test.cts`
- **Verification:** Repeated same-session reads return one exact update command followed by no hint; all update tests pass.
