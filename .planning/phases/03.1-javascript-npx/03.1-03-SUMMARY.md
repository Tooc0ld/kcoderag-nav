## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Preserved Windows hook stdin during the Node version gate**
- **Found during:** Task 2 GREEN launcher subprocess verification
- **Issue:** A separate `node -e` probe under `cmd.exe` consumed the redirected hook input, so the real CJS hook received EOF and emitted nothing.
- **Fix:** Combined the Node 22 check and exported `main()` invocation in one Node process; old/malformed runtimes remain silent because unsuccessful output is buffered and discarded.
- **Files modified:** `plugin-src/hooks/run_hook.cmd`, `tests/hooks/launcher.test.cts`
- **Verification:** Windows Unicode/nested-cwd protocol and all failure cases pass.
- **Committed in:** `85654f0`

**2. [Rule 3 - Blocking] Added an automatically bounded legacy-generator migration window**
- **Found during:** Task 2 GREEN commit hook
- **Issue:** The existing Python pre-commit generator immediately rewrote QA/Dev launchers and version hashes, violating Plans 10/11 which deliberately deploy CJS and launchers in narrow ordered steps; every later commit would also remain blocked.
- **Fix:** The legacy helper now defers only when both canonical launchers point to CJS and staged canonical changes are empty or limited to those launchers. Any unrelated canonical staging or partial staging retains the original hard gate. This exception disappears with the planned Node pre-commit replacement.
- **Files modified:** `scripts/pre_commit_generate.py`, `tests/test_pre_commit_generate.py`
- **Verification:** Five isolated-Git pre-commit tests pass, including positive deferral and non-launcher refusal; the real hook ran successfully on subsequent commits.
- **Committed in:** `85654f0`
