## Decisions Made

- Kept all host paths and configuration formats out of the shared core; future adapters supply only managed roots and complete desired-state data.
- Used a factory-owned validation marker so arbitrary objects cannot reach the transaction engine as trusted desired state.
- Stored recovery payloads only in a mode-restricted project-local recovery tree; the thrown error contains only its safe relative directory name.
- Preserved current-directory/explicit-target semantics exactly and did not add repository-root discovery.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Hardened partial temporary and recovery cleanup**
- **Found during:** Task 2 GREEN review
- **Issue:** A low-level staging or recovery-file write failure could leave an untracked partial temporary file, and deleting recovery data before pruning restored directories could remove the only recovery evidence if cleanup then failed.
- **Fix:** Registered temporary paths immediately, removed partial secure files on propagation, cleaned incomplete recovery trees, and retained recovery until restored-directory pruning succeeds.
- **Files modified:** `src/core/transaction.cts`
- **Verification:** The full stage/commit failure matrix leaves the complete tree unchanged; injected rollback failure retains a valid manifest and backups.
- **Committed in:** `9f63722`
