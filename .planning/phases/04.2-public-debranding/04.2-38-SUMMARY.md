## Request Sequence and Bounds

- Block IDs are base64 encodings of equal-width eight-character ASCII indices beginning at `00000000`; they contain no time, randomness, path, token, or content-derived input.
- Blocks are staged sequentially in ascending byte-offset order and Put Block List commits the same ordered ID list using `<Latest>` elements.
- The signed URL is parsed and cloned, its existing query is preserved, and only `comp=block&blockid=...` or `comp=blocklist` is appended. Pre-existing operation parameters are rejected.
- Data-plane calls use the fixed supported service version `2021-12-02`, exact content lengths, octet-stream block bodies, and XML block-list bodies.
- Default blocks are 4 MiB, accepted block size is capped at 8 MiB, artifact bytes at 64 MiB, block count at 128, data requests at 512, attempts at 5, cancellation cleanup at 5 seconds, and total configured timeout work at 2 hours.
- Only network errors, timeouts, HTTP 408, 429, and 5xx are retryable. Redirects and all other 4xx outcomes are terminal; Create, Finalize, and Delete control calls are never automatically retried.
- Every data-plane response body is cancelled once before retry, progression, or return. Tests prove no `text()`, `json()`, `arrayBuffer()`, stream pull, or canary reflection occurs.
