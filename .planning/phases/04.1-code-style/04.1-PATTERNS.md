## Scope Derived from Context and Research

Phase 04.1 turns the single-purpose navigation installer into a built-in, multi-capability platform. The first two registered capabilities are `kcoderag-navigation` and `code-style-nudge`. A command still targets one host, but the selected capability set is composed into one immutable desired state and committed by one transaction.

The phase adds capability contracts, registry, composition, code-style Skill assets, a shared pre-tool dispatcher, and a stable-session once marker. It modifies the CLI, state schema, four host adapters, project-root bootstrap, generator/package surface, smoke/release evidence, and tests. It removes the unpublished legacy CLI/state/QA-Dev/Python migration and owned-source cleanup paths. Manual or ambiguous external sources remain read-only conflicts and are never adopted or automatically deleted.

### Capability contracts and frozen registry

**Apply to:** `src/capabilities/contracts.cts`, `registry.cts`, `navigation.cts`, `code-style-nudge.cts`

The capability registry should copy the host registry's closed, frozen list plus indexed lookup. This makes the built-in capability set deterministic and rejects unknown IDs before any adapter rendering.

**Analog:** `src/hosts/index.cts:10-24`


Copy these properties:

- Export one frozen ordered `BUILT_IN_CAPABILITIES` collection and one lookup map.
- Give each capability a stable ID, declared assets/hooks/sections, and a pure render contribution. Do not let a capability write files.
- Reject unknown or duplicate selections using stable `InstallError` codes before host detection or transaction work.
- Keep the term `Capability` separate from `NativeHostCapability` in `user-sources.cts`; the latter currently describes observed host inventory, not an installable product.

### Stable-session once marker

**Apply to:** `src/hooks/once-marker.cts`, code-style hook tests

```typescript
const fileAdapter = Object.freeze({
  async createExclusive(filePath: string): Promise<boolean> {
    try {
      const handle = await open(filePath, "wx", 0o600);
      try {
        await handle.sync();
      } finally {
        await handle.close();
```

Required semantic differences from both analogs:

- Require a documented stable host session/conversation ID. If missing, emit no code-style prompt. Never fall back to cwd, process ID, wall-clock window, turn ID, or a random value.
- Marker names are hashes of the stable ID plus capability/version namespace. Marker files are empty; do not store raw IDs, payloads, cwd, tool input, JSON metadata, or code.
- Claim once using exclusive create. Only the winner emits; an existing marker is a no-op.
- The cache is bounded without evicting a live once claim in a way that allows the same stable session to trigger again. When saturated or cleanup is unsafe, fail open by not emitting.
- Every filesystem, parse, permissions, or platform error returns no marker claim and never blocks the host operation.

Do **not** copy `update-check.cts:205-214` cwd/sessionless fallback or its TTL renewal semantics. Do **not** copy `mcp-call-marker.cts:133-142` eviction behavior or JSON metadata payload.
