### Locked Decisions

### 多能力平台与生命周期
- **D-01:** Phase 04.1 只管理随 `kcoderag-nav` npm 包发布的内置 capability。manifest、宿主投影和生命周期接口应可扩展，但不实现远程 registry、Git 下载、传递依赖、第三方信任或来源锁定。
- **D-02:** 未指定 capability 的交互式 `install` 先选择一个宿主，再多选 capability；自动化通过可重复的 `--capability` 显式选择。Navigation 与 `code-style-nudge` 可独立安装。
- **D-03:** `status`/`doctor` 默认展示所选宿主的全部 capability；`install` 添加所选能力；`update` 默认更新全部已安装能力并允许筛选；`uninstall` 必须交互选择或显式指定，绝不默认全删。
- **D-04:** 一次选择的 capability 集合先整体预检，再通过单宿主事务原子写入。任一能力冲突、不支持或漂移时整组不写；不做部分成功。
- **D-05:** 所有权、摘要、状态和配置 section 按 capability 记录。更新或卸载一个能力不得破坏另一个能力、其他宿主或用户配置。
- **D-06:** npm 包内保留一份 canonical Skill 模板；每个 host adapter 将确定性副本写入宿主原生项目目录，并分别记录所有权与摘要。跨宿主不共享受管文件，也不使用 symlink。
- **D-07:** 尚未发布使用的旧 CLI、旧状态 schema 与 QA/Dev 迁移兼容代码直接删除，不提供新旧状态迁移。可能存在的 pre-npm 手工 MCP、plugin、Python Hook 或多来源安装只读检测并硬停止，用户人工清理后重试；nav 不接管、不迁移、不自动删除。

### code-style Skill 打包与规则内容
- **D-08:** Nav 安装纯 Markdown 的 `$code-style-correction` Skill 与独立的 CJS/JS nudge handler。安装后和运行时均不依赖 Python、SVN 或网络。
- **D-09:** Skill 以 `SKILL.md` 为紧凑入口，以自包含的 Markdown `references/` 承载详细规范；不依赖项目外部 Skill 或在线文档。
- **D-10:** Skill 是 nav 完整管理的受管资产，不允许直接编辑或建立 override 文件。项目特殊约定继续放在 `AGENTS.md` 等项目文档中。
- **D-11:** 指令优先级固定为：用户明确要求 > 项目文档 > code-style Skill。发生冲突时说明冲突，不静默覆盖项目约定。
- **D-12:** R01–R19、S01–S08 从 scanner finding 条件改写为写前规范，并保留规则号以便未来审计能力追溯。不得把原扫描器使用说明原样当作新 Skill。
- **D-13:** 首次相关写入只注入短 nudge；Skill 默认加载 27 条规则的紧凑摘要，详细规则仅在当前改动风险相关时读取。不注册逐次写后 Hook。
- **D-14:** 任务结束前由模型对本任务实际修改区域做一次有界自查。明确的自引入问题做最小修正；需要业务判断或契约证据的问题只报告。不使用 SVN、scanner 或 PostToolUse 自查，也不声称“静态扫描通过”。
- **D-15:** Skill 缺失、损坏或摘要漂移时，nudge 静默 fail-open；`status`/`doctor` 报告 `capability_drift`，修复资产后才恢复提示。不使用 handler 内置的简版规则兜底。

### 写前触发与一次性语义
- **D-16:** 扩展名白名单大小写不敏感，固定为 `.c/.cc/.cpp/.cxx/.h/.hh/.hpp/.hxx/.inl/.ipp/.lua`；不按目录排除。
- **D-17:** 只处理能够可靠取得目标路径的结构化 Write/Edit/MultiEdit/apply_patch 类调用，不解析普通 shell。仅内容创建或修改触发；纯删除、纯重命名、未知路径跳过；单次多文件 patch 最多提示一次。
- **D-18:** 有稳定 `session_id`、`thread_id` 或 `conversation_id` 时，每个宿主会话/线程和项目边界只提示一次。没有稳定标识时完全静默，不用 TTL 猜测任务边界，也不逐次重复。
- **D-19:** 一次性 marker 存放在操作系统用户缓存的 `kcoderag-nav/nudges` 下，不污染项目。marker key 由 host、项目边界、capability 和稳定会话标识的哈希组成，不保存 prompt、tool input 或源文件路径；数量必须有界并可清理。
- **D-20:** 通过原子 exclusive create 竞争 marker，只有一个调用可以输出提示。权限、损坏、竞争、创建和清理异常全部静默 fail-open。

### 四宿主支持与版本证据
- **D-21:** 不允许将 instruction-only、toast、用户提示或可阻断事件伪装成 `native_pre_write`。每个 adapter 必须明确报告 delivery mode 与支持证据。
- **D-22:** Claude 使用经官方协议和 fixture 验证的 native pre-write。Codex、Cursor 与 OpenCode 只有在真实宿主 fixture 证明结构化目标路径、稳定会话标识和非阻断模型上下文注入后才允许安装 `code-style-nudge`。
- **D-23:** Codex 与 Cursor 设置经研究验证的最低宿主版本；更旧版本直接拒绝，不降级为 instruction-only。OpenCode 若无法证明非阻断模型上下文注入，也直接拒绝，不降级为 Skill-only 或 toast。
- **D-24:** Adapter 在安装预检中以固定宿主命令、短超时读取并严格解析版本。命令不存在、超时、无法解析或低于最低版本时，对 nudge 返回稳定的 `host_version_unsupported`；不得回显任意子进程输出，也不允许参数绕过。单独安装 navigation 不受 nudge 版本门禁影响。

### 提示正文
- **D-25:** 各宿主的协议包装可以不同，但注入给模型的正文语义固定：在本次 C/C++/Lua 修改前加载并遵循 `$code-style-correction` 的紧凑写前清单；用户和项目指令优先；结束前只自查实际修改区域。正文不包含文件内容、规则全文或“扫描通过”声明。

### Skill 内容研究门

- **D-27:** `04.1-RESEARCH.md` 必须包含：现有内容清单；27 条规则的原意、写前适用性、误报/上下文边界、摘要与详细引用归属、建议动作矩阵；新的 Skill 信息架构与 token 预算；代表性的 C/C++/Lua 正反例和行为验收提示。
- **D-28:** 研究应对照 Agent Skills 规范、OpenAI/Anthropic 官方 Skill 指南和成熟开源 Skill，逐条决定保留、改写、拆分、按需加载、删除或移交未来 `code-style-audit`。研究结论是 plan 的必需输入，不能把 Python scanner 或 SVN 工作流带回 nudge。

## Summary

The phase should be planned as a replacement of the current single-product composition model, not as a second standalone installer. The repository already has the correct write boundary: adapters detect/render, the CLI orchestrates, and `applyTransaction` validates every expected digest, stages all entries, commits state last, and rolls back the selected host. The missing seam is a pure capability projection/composition layer and a capability-scoped state schema. `[VERIFIED: src/hosts/host-adapter.cts:76-93; src/core/transaction.cts:682-839]`

The supplied v5 is complete enough to reconstruct all 27 rule IDs. Its current entrypoint is explicitly an SVN/Python audit workflow, and its historical reference is wholly about revision attribution, SVN reads and cache behavior; those runtime pieces must not ship in `code-style-nudge`. The useful material is the domain intent, correction boundaries, false-positive guards, and evidence discipline. `[VERIFIED: G:/Download/code-style-correction-share-20260825-v5/code-style-correction/SKILL.md:23-47; references/rules.md:231-283; references/historical-revisions.md:1-81]`

Current primary host documentation proves the necessary native shape for Claude and current Codex, but a released minimum version is not established by documentation alone. Cursor documents stable `conversation_id` and `preToolUse`, yet its documented pre-hook output does not establish a non-blocking model-context field. OpenCode documents before/after callbacks but does not establish both a stable session identity and a non-blocking model-context return. Therefore all four adapters need real-host fixtures before a support row is enabled; unsupported rows reject only `code-style-nudge`. `[CITED: https://code.claude.com/docs/en/hooks]` `[CITED: https://developers.openai.com/codex/hooks]` `[CITED: https://prod.cursor.com/docs/hooks]` `[CITED: https://opencode.ai/docs/plugins/]`

**Primary recommendation:** Implement a built-in `CapabilityProjection` registry and a single host composer; install the canonical Markdown Skill plus one host-normalized pre-write handler only where metadata-only fixtures prove all three delivery invariants, and keep deterministic scanner logic for a future capability.

## Project Constraints (from AGENTS.md)

- User runtime is Node.js 22+, compiled `.cts` → executable CJS; no Python, runtime TypeScript compiler, or production dependency. `[VERIFIED: AGENTS.md:25-28,59-76]`
- One command manages one project host; all mutations remain within adapter-declared project files/sections, and cross-host installs may coexist. `[VERIFIED: AGENTS.md:29-32]`
- Drift, symlink, special-file and ambiguous ownership are pre-write hard stops with atomic rollback. `[VERIFIED: AGENTS.md:31-35,119-124]`
- Hook code is bounded, advisory and fail-open: malformed input/errors emit empty stdout and exit 0; model-visible stdout must be protocol-valid. `[VERIFIED: AGENTS.md:119-130]`
- Diagnostics are path-only and secret-safe; never print URL, headers, bearer values, config bodies or subprocess bodies. `[VERIFIED: AGENTS.md:35,121-130]`
- Runtime modules use Node built-ins, `node:` imports, `.cjs` sibling specifiers, strict TypeScript, two-space indentation and deterministic LF output. `[VERIFIED: AGENTS.md:99-117]`
- `src/core/` remains host-neutral; adapters read/render; CLI orchestrates; only the transaction layer writes. `[VERIFIED: AGENTS.md:137-146]`
- OpenCode is project-only and JSON/JSONC coexistence remains a hard stop. `[VERIFIED: AGENTS.md:44,184-191]`
- The authoritative `MCP_QA_EXPERIENCE_GUIDE.md` stays in the sibling KCodeRag repository; phase changes affecting lifecycle/hosts/hooks require a synchronized update there, not a local copy. `[VERIFIED: AGENTS.md:40]`
- Existing unrelated worktree changes must not be overwritten or reverted. `[VERIFIED: AGENTS.md:45]`
- Phase 04.1 D-07 intentionally supersedes the earlier unpublished legacy-decoder/owned-cleanup wording embedded in AGENTS.md; the plan must remove those paths rather than preserve compatibility. `[VERIFIED: .planning/phases/04.1-code-style/04.1-CONTEXT.md:25; AGENTS.md:30,33]`

## Existing Implementation Inventory

### Capability/state/transaction seams

- The current public host IDs are quoted verbatim as `"codex" | "claude" | "cursor" | "opencode"`; current environment is `"qa"`, while legacy input also permits `"dev"`. `[VERIFIED: src/core/contracts.cts:5-7]`
- Current install status values are quoted verbatim as `"healthy" | "not_installed" | "drifted" | "update_available" | "source_conflict" | "invalid"`; they have no capability-level `capability_drift` status. `[VERIFIED: src/core/contracts.cts:10-16]`
- `DesiredState` currently contains `host`, `target`, `managedRoots`, `statePath`, and `entries`; `InstallState` contains `schemaVersion`, `packageVersion`, `host`, `environment`, `managedFiles`, `originals`, `digests`, and optional `sections`. Neither carries capability identity or shared-file contributors. `[VERIFIED: src/core/contracts.cts:86-119]`
- `HostAdapter` currently owns `id`, `managedRoots`, `detect`, `renderInstall`, `renderUninstall`, `status`, and optional source scan/cleanup functions. `[VERIFIED: src/hosts/host-adapter.cts:80-93]`
- `applyTransaction` verifies pre-state and expected digests before writes, stages all entries, commits the state entry last, and executes rollback/recovery on failure. `[VERIFIED: src/core/transaction.cts:692-750,756-839]`

### Hooks and marker seams

- `grep-nudge.cts` already demonstrates bounded JSON parsing, a `PreToolUse` response with `hookSpecificOutput.additionalContext`, and a top-level catch that suppresses all failures. `[VERIFIED: src/hooks/grep-nudge.cts:28-30,306-320,345-370]`
- `update-check.cts` extracts the quoted fields `["session_id", "thread_id", "conversation_id"]`, hashes identity and uses exclusive `"wx"` creation, but its cwd fallback/TTL semantics must not be reused for code-style because D-18 forbids inferred sessions. `[VERIFIED: src/hooks/update-check.cts:64-93,190-214,246-311]`
- `mcp-call-marker.cts` also falls back from session identity and writes a metadata JSON record. code-style must reuse only the cache-root/hash/exclusive-create engineering pattern, not the fallback identity or record body. `[VERIFIED: src/hooks/mcp-call-marker.cts:50-97,113-165]`
- The current generated launcher invokes a single grep-nudge runtime, and current hook config matches `"^(Grep|Glob|Bash)$"`; adding a second independent registration would make shared hook ownership fragile. `[VERIFIED: plugin-src/hooks/hooks.json:1-21; plugin-src/hooks/run_hook.cmd:1-15; plugin-src/hooks/run_hook.sh:1-18]`

### CLI, source gate and packaging seams

- Public commands are quoted verbatim as `"install", "status", "doctor", "update", "uninstall"`. `ParsedArguments` has no capability selection, and the parser currently rejects repeated flags through one `Set`; `--capability` therefore needs a deliberate repeatable-option path rather than a generic duplicate exception. `[VERIFIED: src/cli/commands.cts:38-61,119-180]`
- The CLI selects one adapter, runs source/legacy gates, renders one desired state and calls the transaction once. This is the correct composition point for a selected capability set. `[VERIFIED: src/cli/commands.cts:413-605]`
- `user-sources.cts` defines scan modes `"fast", "deep", "gate"` and a `NativeHostCapability` type that actually represents detected host inventory/version evidence; rename it to avoid collision with product capabilities. `[VERIFIED: src/hosts/user-sources.cts:16-17,50-79]`
- Current state decoding includes `LegacyInstallState`, retired Python state and legacy environment normalization; host adapters import and branch on that decoder. These are the concrete D-07 deletion targets. `[VERIFIED: src/core/state.cts:46-56,255-311,350-436; src/hosts/codex.cts:32-35,924-999; src/hosts/claude.cts:32-35,679-738; src/hosts/cursor.cts:32-33,691-794]`
- Generator products are quoted verbatim as `["qa", "cursor"]`, and package files explicitly enumerate the compiled runtime and generated QA/Cursor trees. Capability assets must replace product-name branching in generator/pack checks and be added to the package allowlist. `[VERIFIED: src/generator/index.cts:91-96,513-670; package.json:9-62]`

### Pattern 1: Projection then composition

Each built-in capability returns an immutable projection: identity/version, dedicated assets, structured section intents, handler contributions, support evidence and status rules. The selected adapter merges all projections into host-native bytes. Only after every projection passes source, version, drift and path checks does the CLI call `applyTransaction` once. `[RECOMMENDED DESIGN, grounded in src/hosts/host-adapter.cts:76-93 and src/core/transaction.cts:682-839]`

Shared files must have a single composite digest plus an ordered contributor/owner set. A capability state record references its own dedicated files and its contributions to shared files; uninstall recomposes shared bytes from remaining installed capabilities rather than restoring a stale whole-file original. `[RECOMMENDED DESIGN]`

### Pattern 2: One dispatcher, independent handlers

The host registers one pre-tool command. The dispatcher parses/bounds input once, calls navigation and code-style handlers independently inside `try/catch`, and emits one protocol response containing only eligible contexts. Removing one capability removes only its registered handler contribution; removing the last pre-tool capability removes the shared registration/launcher. `[RECOMMENDED DESIGN]`

The code-style handler is a routing function, not a rules engine: it checks host evidence, content-mutation shape, path extension, stable session, project boundary, exact Skill digest and once marker, then returns the constant nudge. It never reads source content, parses generic shell, opens SVN, starts Python or calls the network. `[RECOMMENDED DESIGN, constrained by D-08/D-15-D-20/D-25]`

### Pattern 3: Evidence-gated delivery mode

Support data should be generated from checked-in metadata-only fixture receipts rather than inferred from current documentation. A host/capability row is enabled only when the receipt proves: (1) the exact released host version and fixed version command; (2) structured target extraction for create/modify/multi-file patch; (3) a stable session identity across two writes; (4) one non-blocking model-visible sentinel; and (5) the write still completes when the hook fails. `[RECOMMENDED DESIGN]`

Do not reuse the existing Codex/Claude navigation minimum versions as code-style minimums: those values prove a different source-inventory/navigation contract, not D-22 native pre-write delivery. `[VERIFIED: src/hosts/codex.cts:104-142; src/hosts/claude.cts:88-121]`

### Pattern 4: Bounded once marker without task inference

Use the first non-empty stable host field only, normalize the real managed project root, hash `host + project + "code-style-nudge" + stableId`, and exclusive-create an empty marker. Do not fall back to cwd/turn/tool ID and do not store JSON metadata. `[RECOMMENDED DESIGN, constrained by D-18-D-20]`

For strict at-most-once semantics under a bounded cache, never evict an arbitrary marker merely to admit a new one. Use a fixed tested capacity (1024 is the recommended implementation constant). Automatic removal is allowed only when a real-host fixture proves that host's `SessionEnd` carries the same stable identity needed to target the exact claim; hosts without that proof perform no automatic eviction of possibly live claims. At capacity, silently suppress unknown new sessions. The documented manual cleanup contract is: close every related host session first, then delete only the OS user-cache `kcoderag-nav/nudges` directory. `status`/`doctor` remain read-only and expose at most safe count/state; cleanup failures are fail-open and never affect the original write. `[LOCKED RESOLUTION]`

### Pattern 5: Legacy means detect/refuse, not decode

Delete legacy state parsers, migration authorities and owned-source cleanup planning. The new state parser accepts only the new capability schema. Manual-source detection uses a closed metadata-only allowlist: existence, filesystem type, bounded structural key names, and a known managed identity are the only permitted observations. It never reads or emits credential values, configuration bodies, hook bodies, arbitrary subprocess output, or source content. A known signature produces a stable secret-safe conflict with a safe path; any unknown, partial or ambiguous match also hard-stops. No source is adopted, migrated, rewritten or deleted. `[LOCKED RESOLUTION, constrained by D-07]`

### Anti-Patterns to Avoid

- **Copy v5 unchanged:** it instructs `svn`, Python scanning, historical cache, reruns, builds and deployment evidence; those belong outside this nudge. `[VERIFIED: v5 SKILL.md:23-47]`
- **Embed 27 rules in handler:** asset drift could silently fall back to different semantics and every invocation would duplicate content; handler must stay constant and Skill-owned. `[VERIFIED: .planning/phases/04.1-code-style/04.1-CONTEXT.md:33-35,51]`
- **Use TTL as session identity:** TTL permits periodic repeats and guesses task boundaries; missing stable ID must be silent. `[VERIFIED: .planning/phases/04.1-code-style/04.1-CONTEXT.md:40]`
- **Parse Bash/shell to find writes:** aliases, quoting and redirection make target extraction unreliable and expand the prompt-injection surface. `[VERIFIED: .planning/phases/04.1-code-style/04.1-CONTEXT.md:39]`
- **Use blocking output/toasts as context:** delivery is supported only if the model receives non-blocking context and the original write completes. `[VERIFIED: .planning/phases/04.1-code-style/04.1-CONTEXT.md:45-48]`
- **One transaction per capability:** creates partial installation and inconsistent shared hooks. `[VERIFIED: .planning/phases/04.1-code-style/04.1-CONTEXT.md:22]`
- **Store a whole shared config file under each capability:** independent uninstall would restore stale bytes and destroy another contributor. `[RECOMMENDED DESIGN]`
- **Guess host minimum versions:** current docs/source describe current behavior, not the earliest released build. `[VERIFIED: .planning/phases/04.1-code-style/04.1-CONTEXT.md:46-48]`

## Common Pitfalls

### Pitfall 1: Shared-file ownership makes independent uninstall destructive
**What goes wrong:** both capabilities record the same `hooks.json` or launcher as an independently restorable whole file.
**Why:** file ownership is modeled as one product rather than contributor sections.
**Avoid:** compose shared bytes from the installed capability set and record contributor IDs plus one composite digest.
**Warning:** uninstalling code-style removes navigation hooks or reports false drift. `[RECOMMENDED DESIGN]`

### Pitfall 2: Current-host documentation is mistaken for a minimum version
**What goes wrong:** adapter pins an invented minimum or reuses an unrelated navigation minimum.
**Avoid:** fixture released binaries and label the lowest passing build “lowest proven.”
**Warning:** support table has a version with no receipt digest. `[VERIFIED: .planning/phases/04.1-code-style/04.1-CONTEXT.md:46-48]`

### Pitfall 3: Marker eviction violates once semantics
**What goes wrong:** LRU/TTL removes a still-live session marker and the next edit nudges again.
**Avoid:** no TTL; at capacity suppress unknown new sessions instead of evicting arbitrary markers. Automatically clean only from fixture-proven exact SessionEnd identity; otherwise require the documented close-all-sessions/manual cache cleanup contract.
**Warning:** tests can trigger a second nudge by advancing a clock. `[RECOMMENDED DESIGN]`

### Pitfall 4: Asset drift silently changes the rules
**What goes wrong:** handler includes an embedded fallback checklist when the managed Skill is missing.
**Avoid:** verify state and exact asset digest; handler emits nothing and diagnostics report `capability_drift`.
**Warning:** nudge still appears after editing/deleting `SKILL.md`. `[VERIFIED: .planning/phases/04.1-code-style/04.1-CONTEXT.md:35]`

### Pitfall 5: Prescriptive guidance is reported as scanner proof
**What goes wrong:** model says “R01–R19 passed” or “encoding clean” after a visual review.
**Avoid:** explicit evidence-boundary section and eval assertions against scan/build/encoding claims.
**Warning:** handoff contains “passed” without a named external command/fixture. `[VERIFIED: .planning/phases/04.1-code-style/04.1-CONTEXT.md:34; v5 rules.md:276-283]`

### Pitfall 6: Manual source detection reads secrets
**What goes wrong:** doctor serializes MCP config bodies or version-process output to explain a conflict.
**Avoid:** inspect only bounded structure/path/fingerprint metadata and emit stable code + safe relative path.
**Warning:** snapshots contain URL, header, bearer, command body or arbitrary stdout. `[VERIFIED: AGENTS.md:121-130]`

### Pitfall 7: Python/SVN survives through tests or generated assets
**What goes wrong:** runtime is Node-only but pack still includes v5 scripts, historical docs or default SVN prompt.
**Avoid:** pack allowlist and retirement audit forbid `.py`, SVN workflow phrases and scanner launchers under the capability asset tree.
**Warning:** packed tarball contains `historical-revisions.md`, `audit_added_lines.py` or `agents/openai.yaml` unchanged. `[VERIFIED: .planning/phases/04.1-code-style/04.1-CONTEXT.md:28,56]`

### Pitfall 8: Handler parses arbitrary file content
**What goes wrong:** source text/path becomes prompt content or triggers false positives, raising token/security cost.
**Avoid:** parse only bounded structured tool metadata sufficient to classify target and mutation; emit a constant nudge.
**Warning:** hook output varies with source bytes or includes filenames. `[VERIFIED: .planning/phases/04.1-code-style/04.1-CONTEXT.md:39,41,51]`
