<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Repository/generated tree → npm tarball | Exact public bytes must exclude every retired product path. |
| Git subject/evidence/remote CI → release authority | Review artifacts and remote jobs may refer to stale or self-referential commits. |
| Real Head metadata → acceptance receipt | Project/user evidence may contain secrets or hide unrelated mutation. |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-11-01 | Tampering | package inventory | critical | mitigate | Enforce exact repository/tar member sets and five independent retired-product seam failures. |
| T-04-11-02 | Spoofing | pre-release subject binding | critical | mitigate | Require identical immutable subject SHA/tree, evidence-only child commit, final remote head, and exact successful four-lane CI. |
| T-04-11-03 | Repudiation | verdict artifacts | high | mitigate | Closed verdict/schema/coverage checks reject missing requirements, decisions, or open blocking findings. |
| T-04-11-04 | Information Disclosure | Head/public evidence | critical | mitigate | Exact-key metadata-only validators reject config, URL, header, token, command, path, and process bodies. |
| T-04-11-05 | Spoofing | degraded Head cleanup evidence | critical | mitigate | Validator binds exact safe registration identity/fingerprint and requires successful complete post-removal absence before project writes. |
| T-04-11-SC | Tampering | npm package acquisition | high | mitigate | Head acceptance cross-checks exact official 0.2.0 receipt, integrity, tar hash, gitHead, and release SHA. |
